欢迎阅读 Sparrow UI 文档！🐦

## 什么是 Sparrow UI

Sparrow UI 是一个**基于数据包的响应式 UI 库**，支持 **Paper / Folia**，Spigot 为实验性支持。你可以用 Item 做按钮，用 Pane 排布局，用 Inventory 存放物品，再通过 Window 把菜单打开给玩家。同一组组件可以供多个窗口和多名玩家共用。

:::info

菜单通过数据包显示，不需要创建 Bukkit 容器。格子内容和原版控件由 Sparrow UI 控制，叠加的视觉效果、动画不会修改库存里的真实物品。

:::

## 核心功能

- **🖼️ 全面的原生菜单 API**，支持箱子、铁砧、酿造台、制图台、合成器、工作台、发射器、投掷器、附魔台、三种熔炉、砂轮、漏斗、商人交易、锻造台和切石机。每种菜单都有独立的 Window API，进度、按钮、配方书、交易、地图预览这些原生功能都能控制。

- **⏳ 菜单物品异步渲染**，Item 支持同步和异步两种模式，可以直接生成物品，也可以等待数据库查询结果。等待期间先显示占位物品，过期的结果也不会覆盖新内容。

- **🧩 多个窗口共用组件**，同一个 Item、Pane 或 Inventory 可以同时给多扇 Window、多名玩家用。修改组件后，正在显示它的窗口会刷新受影响的格子。

- **📦 虚拟容器与映射容器**，`VirtualInventory` 可以像普通箱子一样放入、取出、拖拽、Shift 转移和数字键交换，还支持槽位规则、堆叠上限和持久化。`ReferencingInventory` 能把玩家背包、Bukkit 容器或自定义存储接进菜单，共享容器也可以让多名玩家同时操作。

- **🔄 容器交互事务系统**，一次点击会被整理成完整事务，包含相关 Inventory、槽位变化、光标、副手和掉落物。系统兼容 Bukkit 的 `InventoryClickEvent` 和 `InventoryDragEvent`，还提供可以查看、修改或取消整笔操作的 Sparrow 事件。事件取消或并发冲突时，不会写入部分结果。

- **🧭 多 Window 菜单会话**，`WindowSession` 提供栈、保留栈和树三种结构，负责窗口跳转、返回、Esc 返回、等待异步构建的窗口，以及结束整个会话。重新打开被保留的 Window 时，原来的页码、滚动位置和菜单数据都还在。

- **✨ 分层视觉与动画系统**，可以为 Inventory、Pane、Window、光标和标题设置视觉效果，库存里的真实物品保持不变。设在 Inventory 或 Pane 上的效果所有观察者都能看到，设在 Window 上就只影响当前玩家，还可以叠加播放多个动画。

- **⚡ 数据变化后自动更新菜单**，Signal 支持映射、组合、异步加载、轮询、防抖和节流，还有 List、Set、Map 和按玩家分区的状态。Item 和 Pane 可以直接声明依赖，订阅采用弱引用；不再有人订阅后，相关轮询任务会停止，派生结果也不再主动计算。

- **📄 基于 Signal 的翻页系统**，Page 把当前内容、页码、总页数和实际条目数都公开成 Signal，支持动态列表、按页分区数据和数据库异步加载，还带缓存、刷新和预取。Scroll 和 Tab 也提供相应的状态 Signal。

- **🖥️ 面向 Folia 的线程安全设计**，Window 的生命周期和协议操作会在玩家实体线程里串行执行，共享组件和虚拟容器允许来自不同玩家线程的并发访问。事务系统用固定锁序和版本校验来避免死锁和过期写入，同时保留 Bukkit 对实体和区域线程原有的约束。

:::warning[公开 API 仍可能调整]

Sparrow UI 目前处于 Beta 阶段，正式版之前公开 API 还会继续变动。升级版本时请留意变更说明。

:::
