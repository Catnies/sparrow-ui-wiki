技能点由技能树菜单、属性菜单和升级提示共同使用，每名玩家一份。Alice 升级拿到技能点，Bob 的菜单不应该跟着刷新。

每名玩家一份状态，最直接的做法是 `Map<Player, ...>`。可 `Player` 对象和这次连接绑定，玩家退出后它还留在表里，时间一长就是内存泄漏，退出时的清理也得自己写。

## 玩家分区做什么

用 UUID 作为 [KeyedSignal](/signal/keyed/basics) 的 key，每名玩家就有自己独立的分区。再调用一次 `Signals.evictOnQuit(signal)`，之后任何玩家退出服务器，Sparrow UI 都会对它调用 `remove(uuid)`，清掉这名玩家的分区。

同步、异步、轮询三种分区来源都可以这样登记。

## 每名玩家的技能点

技能点在插件启动时创建一次，放在一个服务类里，多个菜单共用。

```java
public final class SkillPoints {
    private final MutableKeyedSignal<UUID, Integer> points = KeyedSignal.of(playerId -> 0);

    public SkillPoints() {
        Signals.evictOnQuit(this.points);  // 玩家退出时清理他的分区
    }

    public MutableSignal<Integer> of(Player player) {
        return this.points.at(player.getUniqueId());
    }

    public MutableKeyedSignal<UUID, Integer> points() {
        return this.points;
    }
}
```

下面的演示里，`alice` 和 `bob` 是两名玩家的 UUID，菜单里的两个物品分别依赖他们的分区。

## 按玩家异步加载

每名玩家的战绩存在数据库里，用 `KeyedSignal.async` 按 UUID 加载，退出时清理。

```java
KeyedSignal<UUID, PlayerStats> stats = KeyedSignal.async(
        (PlayerStats) null, ioExecutor, statsRepository::load
);
Signals.evictOnQuit(stats);

Signal<PlayerStats> own = stats.at(viewer.getUniqueId());
```

`statsRepository.load(UUID)` 和 `PlayerStats` 与 [async](/signal/source/async) 页相同。资料页和排行榜页对同一名玩家调用 `at`，共用一份查询结果。战绩写入数据库后，调用 `stats.dirty(playerId)` 刷新那名玩家。

需要同步其他子服的修改时，把 `async` 换成 `polling` 或 `pollingMillis`，只有正在被查看的玩家分区才会轮询。

## 在菜单里使用

一个共用的按钮要显示「当前查看者」的技能点，就在 `dependsOn` 里从渲染上下文取出查看者的 UUID。

```java
Item pointsButton = Item.builder()
        .dependsOn(points, context -> context.player().getUniqueId())
        .setItemProvider(context -> {
            int value = points.get(context.player().getUniqueId());
            return new ItemStack(Material.EXPERIENCE_BOTTLE, Math.max(1, value));
        })
        .addClickHandler(click -> {
            points.update(click.player().getUniqueId(), value -> value + 1);
        })
        .build();
```

Alice 和 Bob 看着同一个按钮，各自绑定自己的分区，Alice 点击后只刷新她看到的那一个。完整说明见 [玩家与分区显示](/signal-ui/player)。

## 注意事项

:::warning[来源要由你保存]
Sparrow UI 只弱引用登记过的来源，来源本身要由你持有，比如上面的 `points` 字段。来源被回收后，登记也随之失效。重复登记同一个对象只算一次，插件关闭时所有登记自动解除。
:::

:::warning[清理只是移除缓存]
退出后再访问这名玩家的分区，会用初始化函数重建，离线玩家的 UUID 也可以照常读写。需要持久保存的数据，要自己写入数据库。使用前要先完成 Sparrow UI 的 [初始化](/getting-started/installation#初始化)。
:::

:::tip[什么时候用不着玩家分区]
状态只属于某一扇窗口时，比如确认框里的勾选项、这次打开时的页码，直接为这扇窗口创建一个普通的 `MutableSignal` 就够了，窗口关闭，状态也就不要了。需要在多个菜单之间共享，或者菜单关闭后还要保留的每名玩家状态，才放进玩家分区。
:::
