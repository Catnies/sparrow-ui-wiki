Window 管窗口，Pane 排布局，Element 描述每一格的内容。Pane 可以继续嵌套，也可以有多块 Pane 同时接入一扇 Window。

## 打开菜单时，组件从哪来

这些组件里，**Window 是按玩家算的**。Pane 和 Element 都不记录自己在哪一格、给谁看，所以有两种用法：每名玩家各建一份，或者大家共用一份。

|  | 每次打开新建 | 共享同一份 |
|---|---|---|
| 适用 | 绝大多数菜单 | 多人应该看到同一份内容 |
| 玩家之间 | 互不干扰 | 一处变化，所有人立刻看到 |
| 要注意什么 | 没有额外约束 | 组件里不能存玩家状态 |

### 每次打开新建

菜单对象很轻，构建过程只是解析一段字符模板再造几个物品，没有 IO。所以**默认就这么写**，[快速开始](/getting-started/quick-start) 用的也是这种：

```java
public static void open(Player viewer) {
    // 每次调用都建一份新的 Pane 和 Window
    Window.builder(buildPane())
            .setTitle(Component.text("欢迎菜单"))
            .open(viewer);
}
```

每名玩家拿到的是互不干扰的一套组件，不用考虑并发，也不用担心上一个玩家留下的状态。**拿不准就用这种。**

### 共享同一份

把同一个 Item、同一块 Pane 或同一个容器给多扇 Window 用。组件变化后所有观察者都会收到通知，每扇 Window 只刷新受影响的格子。

适合那种内容本来就该所有人一样的场景，比如公共仓库、全服排行榜。

```java
// 一块公告 Pane，两名玩家各开一扇窗看同一份内容
Window.builder(boardPane).setTitle(Component.text("公告")).open(alice);
Window.builder(boardPane).setTitle(Component.text("公告")).open(bob);
```

:::warning[共享时不能在组件里存玩家状态]
这条**只在共享时成立**。既然一个组件同时给多名玩家用，就不能在它内部缓存"当前玩家是谁"。需要按玩家区分的东西，从 `RenderContext` 或 `ItemClick` 里取。

上面"每次打开新建"的写法不受这条限制。
:::
