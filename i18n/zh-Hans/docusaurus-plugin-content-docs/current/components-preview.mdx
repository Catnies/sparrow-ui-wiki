## ThreadBadge

标注某个 API 必须在哪条线程上调用。四种类型，另外可以用 children 覆盖文案。

- `Window#open()` <ThreadBadge type="viewer" />
- `VirtualInventory#add()` <ThreadBadge type="any" />
- `Signal.async(...)` 的 loader <ThreadBadge type="async" />
- `Bukkit.getScheduler()` <ThreadBadge type="main" />
- 自定义文案：<ThreadBadge type="async">Paper 全局异步调度器</ThreadBadge>

在正文里它是行内元素，跟在方法名后面不会撑开行高：调用 `ReferencingInventory#refresh()` <ThreadBadge type="viewer" /> 之前，必须确认当前上下文可以访问被引用的容器，否则平台异常会原样抛出。

## MinecraftSlotGrid

将结构模板画成 Minecraft 容器，支持 `rows`、`legend`、`empty`、`showSlots`、`caption`、`title` 和 `scale`。

这是**布局视图**：每一格都显示自己的标志符，留空位的 # 也照样显示，因为读者要对着它数"哪个字符落在哪一格"。留空位不套彩色方块；传入 `icons` 可以把指定标志符替换成物品贴图。

几何与配色逐条对齐 minecraft.wiki 的 mcui / invslot 体系，数值取自那边的实际 CSS。悬停时只有指着的那一格发白（游戏行为），同标志符的其余格子用白色外框指认。

要展示"玩家最终看到什么"用下面的 `<MinecraftWindow>`，不要用这个。

<MinecraftSlotGrid
  title="欢迎菜单"
  rows={["#########", "###G#C###", "#########"]}
  legend={{'#': '装饰背景', G: '打招呼', C: '关闭菜单'}}
  showSlots
/>

`scale={2}` 等比放大一倍，标志符看得更清楚，像素依旧对齐：

<MinecraftSlotGrid
  title="实时搜索"
  rows={["MMMMMMMMM", "MMMMMMMMM", "MMMMMMMMM", "P###I###N"]}
  legend={{M: '搜索结果', P: '上一页', I: '筛选状态与页码', N: '下一页', '#': '空位'}}
  scale={2}
/>

多字符标志符（反引号写法）用 `scale={2}` 才放得下：

<MinecraftSlotGrid
  rows={["`confirm`#`cancel`", "###", "`title`##"]}
  legend={{
    confirm: '确认按钮',
    cancel: '取消按钮',
    title: '标题物品',
    '#': '空位',
  }}
  scale={2}
/>

按标志符展示物品贴图，图例中的图标也会同步更新：

<MinecraftSlotGrid
  title="欢迎菜单"
  rows={["#########", "###G#C###", "#########"]}
  icons={{'#': 'gray_stained_glass_pane'}}
  legend={{'#': '灰色玻璃板', G: '打招呼', C: '关闭菜单'}}
/>

传入 `items`（写法同 `<MinecraftWindow>`）后右侧出现「字符模板 / 玩家视角」切换，同一个菜单不必再把布局图和成品图各放一张。两种视图外框尺寸一致，切换时不跳动；玩家视角下图例换成物品贴图，悬停图例仍会描出同标志符的格子。`defaultView="game"` 可让它默认显示成品：

<MinecraftSlotGrid
  title="欢迎菜单"
  rows={["#########", "###G#C###", "#########"]}
  legend={{'#': '装饰背景', G: '打招呼', C: '关闭菜单'}}
  items={{
    '#': {icon: 'gray_stained_glass_pane'},
    G: {icon: 'lime_dye', name: '打个招呼', nameColor: '#ffff55', lore: ['点一下, 向自己问好。']},
    C: {icon: 'barrier', name: '关闭', nameColor: '#ff5555'},
  }}
/>

模板语法错误会就地显示原因：

<MinecraftSlotGrid rows={["ABCDE", "ABC"]} />

<MinecraftSlotGrid rows={["A`unterminated"]} />

铁砧上栏这种极小的 Pane：

<MinecraftSlotGrid title="铁砧" rows={["###"]} legend={{'#': '冻结的空槽'}} showSlots />

## MinecraftWindow

用**原版 GUI 贴图 + 原版物品图标**模拟一扇打开的容器。和 `<MinecraftSlotGrid>` 分工明确：那个讲布局（每格显示标志符），这个讲成品（每格显示真实物品）。

悬停显示 Minecraft 样式的 Tooltip，跟随鼠标并在浏览器边缘自动避让。此组件只展示菜单外观。

<MinecraftWindow
  type="chest"
  rows={3}
  title="欢迎菜单"
  layout={["#########", "###G#C###", "#########"]}
  items={{
    '#': {icon: 'gray_stained_glass_pane'},
    G: {icon: 'lime_dye', name: '打个招呼', nameColor: '#ffff55', lore: ['点一下, 向自己问好。']},
    C: {icon: 'barrier', name: '关闭', nameColor: '#ff5555', lore: ['点一下, 关掉这个菜单。']},
  }}
/>

窗口类型与槽位坐标在 `src/components/mcWindows.js`，目前有 `chest`（行数可变）、`crafting`、`anvil`、`hopper`。加新类型只要照着贴图量一遍坐标填进那张表，不用动组件。

默认只画容器本身。正文真的要讲下半区时才打开 `playerInventory`：

<MinecraftWindow

## Exercise

三段式思考题：需求常驻，实现思路和参考实现默认收起。放在讲完一个功能之后，让读者先自己过一遍再对答案。两个子块都是可选的。

<Exercise title="让翻页按钮在首页和末页变灰">

菜单底部有上一页、下一页两个箭头。现在无论在第几页，两个箭头都是同一个亮起来的样子，玩家点到底了也没有任何反馈。

要让箭头在到头时换成灰色染料，并且不再响应点击。

<ExerciseApproach>

按钮的外观取决于当前页码和总页数这两个值，所以它不能再是一个固定的 `ItemStack`——得让它在这两个值变化时重新渲染一次。

</ExerciseApproach>

<ExerciseAnswer>

```java
Item.builder()
        .dependsOn(page.page(), page.count())
        .setItemProvider(context -> {
            boolean enabled = page.page().get() + 1 < page.count().get();
            return new ItemStack(enabled ? Material.ARROW : Material.GRAY_DYE);
        })
        .addClickHandler(click -> page.advance(1))
        .build();
```

</ExerciseAnswer>

</Exercise>

只给需求、不给答案也可以：

<Exercise>

装饰背景占了 22 格，每一格都是同一个 `ItemStack` 实例。这样做有没有问题？

<ExerciseApproach>

Pane 的背景只负责"没被单独安排的格子显示什么"，它不参与交互，也不持有任何逐格状态。

</ExerciseApproach>

</Exercise>
